## 1. What Flamescope is

Flamescope turns NASA microgravity flame-spread experiments into evidence that crews and mission planners can search and trust. It does three things:

1. **Collects the evidence into one table,** one row per experiment run, plus a corpus of source passages. Every row and passage links back to its NASA source.
2. **Summarizes, ranks, and interprets.**
   - Insight cards state what the data shows.
   - A ranking orders runs by how close their oxygen and pressure are to the Moon or Mars cabin atmosphere.
   - A question box answers in plain English with citations.
3. **Refuses rather than guesses.** A number appears only if it matches a field in the run table. A question the sources can't answer gets a refusal.

The headline finding, computed from the tables: Moon habitats are planned at 34% oxygen and 56.537 kPa, and no run in the table with a recorded pressure burned below 101.325 kPa. Fire at lunar habitat pressure is untested in this corpus.

## 3. Architecture

```
NASA NTRS API ─┐                                   ┌─> data/runs.csv (+ split files)
NASA PSI API ──┼─ fetch.py ─> raw/ ─ extract.py ─┐ │
               │                                 ├─ build.py ─┼─> data/chunks.jsonl
data/manifest.csv (no entry, no ingest)          │ │          └─> data/bm25_index.json
data/runs_curated.csv (from paper text) ─────────┘ │
                                                   ├─ embed.py ───────> data/embeddings.npy (blocked: HF access)
                                                   ├─ groq_generate.py ─> data/llm_answers.json (key stays local)
                                                   ├─ eval.py ────────> data/eval_report.json
                                                   └─ export.py ──────> web/data.js ─> GitHub Pages (web/)
```

The site is fully static: `web/index.html` loads `web/data.js` (`window.DATA`) and `web/app.js`. Search runs in the browser. The site makes only one kind of network call: when a visitor turns on live mode with their own key, it calls api.groq.com.

## 5. Running it

```bash
./pipeline.sh
```

```bash
python3 -m http.server 8765 --directory web
```

- **Python 3.15** runs the standard-library steps.
- **`.venv` (Python 3.14)** holds `sentence-transformers`, torch, and pyyaml for `embed.py` and `groq_generate.py`. Create it with `uv venv --python 3.14 .venv && uv pip install --python .venv/bin/python sentence-transformers`.
- **Groq:** put `GROQ_API_KEY=...` in `.env` (gitignored) or export it in your shell. Without it, step 4b is skipped.
- **Embeddings:** need a Hugging Face login with access granted to `google/embeddinggemma-300m`. Without it, step 4 fails and the pipeline continues on BM25 alone.

## 6. Data contract

### `data/runs.csv`: one row per run, never per campaign
| Column | Meaning |
|---|---|
| `run_id` | `FS-####`. FS-0001 to FS-0011 come from paper text; FS-1001 and up come from PSI tables. |
| `doc_id` | Source in the manifest |
| `source_url` | **Required.** NTRS citation page or PSI investigation page. |
| `experiment`, `mission`, `sample` | As stated in the source. Left blank if not stated. |
| `platform`, `platform_group` | `iss`, `drop_tower`, `parabolic_flight`, `shuttle`, `cygnus`. Each group is shown separately. |
| `gravity_condition` | Every current row is `microgravity` |
| `question_answered` | `transport`, `habitat`, or `long-duration`. Blank until the team sets the mapping rule (flagged). |
| `fuel`, `fuel_geometry`, `fuel_dimension_as_reported` | Material and size, as reported |
| `o2_fraction_pct`, `o2_units`, `o2_as_reported` | **Required.** Percent by volume. A number is stored only if the source gives a single value. |
| `total_pressure_kpa`, `pressure_as_reported` | **Required.** In kPa (1 atm = 101.325 kPa). |
| `flow_condition`, `flow_velocity_m_s` | In m/s. "Quiescent" alone is not turned into a number. |
| `spread_rate_mm_s`, `spread_rate_as_reported` | In mm/s. Left blank if the source shows it only in a figure. |
| `outcome`, `outcome_notes` | **Required.** `spread` or `no_spread`, with the evidence. The notes say when an outcome was inferred from an abstract. |
| `source_location` | Page, section, or table row |
| `data_quality_flag` | Every blank or uncertain field, named |
| `extraction_method` | How the row was produced (see SI table) |
| `verification_status` | `unverified`, then `checked_against_source` or `conflict_found` after a second person checks it |

**Rules:**
- A row missing any required field goes to `runs_excluded_missing_required.csv`. It is excluded, never ranked low.
- `runs_ranked_view.csv` holds verified rows only. Conflict rows never enter it.
- Nothing is filled in from memory or inference.

### Other contract files
- **`data/manifest.csv`:** `doc_id`, `title`, `source_url`, `doi`, `source_type`, `date_retrieved`, `license_or_terms`, `retrieval_status`, `seed_status`, `notes`. A source with no entry is not ingested.
- **`data/chunks.jsonl`:** `chunk_id`, `doc_id`, `run_ids`, `section`, `page_or_paragraph`, `text`, `source_url`, `doi`, `date_retrieved`, `approx_tokens`, `chunk_type`, `ai_assisted`.
- **`data/atmosphere_targets.csv`:** Moon (cited, pending team lead confirmation) and Mars (needs a citation).
- **`data/eval_set.json`:** 20 answer or unsupported questions plus 5 off-topic questions. Each has gold run and chunk IDs.
- **`data/llm_prompt.json`:** the single grounded-answer prompt, shared by the offline and live paths.
- **`data/llm_answers.json`:** generated by step 4b. Only `validated` and `refused` answers are exported to the site.

## 7. Guardrails, all enforced in code
- **Units:** conversions must reproduce the as-reported value (`build.py`).
- **Numbers:** the number rule (`eval.py` `numbers_ok`, mirrored in `web/app.js` `checkAnswer`) applies to insight cards, gold answers, and every LLM answer. Each number must be a field value of a cited run or an atmosphere target.
- **Citations:** must exist as a run, chunk, or atmosphere ID.
- **Copyright:** excerpts from copyright-flagged papers are capped at 70 words each (`build.py`).
- **Licensing:** PSI sources must carry a license before they are ingested (`fetch.py`).
- **The Groq key never ships with the site.**
  - Offline, the key is read from the environment or `.env` and never written anywhere.
  - Live, the visitor's own key is kept in session storage and sent only to api.groq.com.
- **Links:** source links must be https only, and all page text is HTML-escaped (`web/app.js`).
